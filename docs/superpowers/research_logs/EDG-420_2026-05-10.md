## Objective
Add a calibration gate for `_unlabelled_ dt0` rescue strict-probe fallback so rescue predictions do not automatically collapse to infrastructure unless there is matching infrastructure lexical evidence (or rescue lexical evidence is absent).

## Code Changes
Files:
- `triage_sandbox.py`
- `tests/test_triage_sandbox.py`

### `triage_sandbox.py`
1. Added config toggle:
   - `TRIAGE_UNLABELLED_DT0_RESCUE_INFRA_FALLBACK_GATE` (default `1`)
2. Added helper:
   - `should_fallback_unlabelled_dt0_rescue_to_infra(has_rescue_lexical_evidence, has_infrastructure_lexical_evidence, gate_enabled=True)`
3. Wired strict-probe rescue-failure branch to:
   - compute rescue/infra lexical evidence once,
   - preserve lexical-confirmation override behavior,
   - apply fallback only when helper permits,
   - otherwise keep rescue prediction.
4. Included new toggle in `compute_state_hash()` to maintain dedupe correctness.

### `tests/test_triage_sandbox.py`
Added coverage for:
- state-hash sensitivity to `TRIAGE_UNLABELLED_DT0_RESCUE_INFRA_FALLBACK_GATE`
- fallback gate behavior in four scenarios:
  - infra evidence present -> fallback allowed
  - no rescue evidence -> fallback allowed
  - rescue-only evidence -> fallback blocked
  - gate disabled -> fallback allowed
