# EDG-345 - Latency Outlier Guard for Optimization Loop (2026-05-02)

## Objective
- Reduce false regression churn in the autonomous optimization loop when host/runtime jitter produces occasional latency spikes (for example, ~270 ms outliers on otherwise ~160 ms stable state hashes).
- Preserve strict F1 and latency gating while marking clearly non-comparable variance runs as `blocked` instead of normal `discard`.

## Change Summary
- Added robust same-hash latency history helper:
  - `load_recent_keep_latencies_for_state_hash(...)`
- Added explicit outlier detector helper:
  - `detect_latency_outlier_for_state_hash(...)`
- Added configurable outlier knobs:
  - `TRIAGE_LATENCY_OUTLIER_LOOKBACK` (default `30`)
  - `TRIAGE_LATENCY_OUTLIER_MIN_SAMPLES` (default `2`)
  - `TRIAGE_LATENCY_OUTLIER_RATIO` (default `1.45`)
- Updated status decision path:
  - when a run is currently `discard`, and there are enough comparable same-hash keep runs,
  - if `avg_latency > median(same_hash_keep_latencies) * TRIAGE_LATENCY_OUTLIER_RATIO`,
  - relabel as `blocked` with explicit outlier note.

## Why This Helps
- Prevents host-variance spikes from being treated as meaningful architecture regressions.
- Keeps the optimization ledger cleaner for promotion/rollback decisions.
- Maintains conservative behavior: only triggers with enough prior comparable samples and a large multiplicative deviation.
