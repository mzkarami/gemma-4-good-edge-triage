## Problem Statement
- EDG-352 already short-circuited duplicate `post-load gpu telemetry unavailable` blocked states.
- A second duplicate blocked pattern remained: repeated pre-import low-VRAM CPU-guard blocked states still traversed runtime setup before early exit.
- On recurring heartbeats with unchanged state hash, this incurred avoidable initialization overhead.

## Code Change (r1)
Updated `triage_sandbox.py` with a pre-load duplicate guard check right after state hash resolution:
- New early exit applies when all are true:
  - `TRIAGE_PREIMPORT_CPU_GUARD_ACTIVE=1`
  - `N_GPU_LAYERS > 0`
  - `TRIAGE_ALLOW_GUARDED_CPU_BENCHMARK=0`
  - a prior blocked row exists for same `state_hash` containing:
    - `pre-import low-vram cpu guard active`
- In that case, `run_triage()` now:
  - returns `{"status": "blocked", "state_hash": current_hash}`
  - calls `cleanup_after_run()`
  - skips chat-handler and model initialization.
