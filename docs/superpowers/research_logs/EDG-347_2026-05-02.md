# EDG-347 - Optimization Loop Comparability Hardening (2026-05-02)

## Objective
- Stabilize autonomous keep/discard decisions under shared-host variance without weakening F1 or latency quality gates.
- Ensure blocked safety states are deduped correctly while still allowing re-evaluation of comparable experimental states.

## Change Summary
- Kept `blocked` rows out of state-hash dedupe (`DEDUP_STATUSES` now excludes `blocked`) so legitimate reruns are not starved by non-comparable runs.
- Added blocked-state dedupe helper:
  - `has_blocked_reason_for_state_hash(...)`
- Hardened state hashing for comparability:
  - upgraded to `sha256`
  - hashes full image payload bytes (not partial chunks)
  - includes probe-budget/runtime guard knobs
  - excludes transient pre-import guard activation bit
- Added targeted probe budget limiter:
  - `consume_probe_budget(...)`
  - route-level accounting and fallback route metric (`probe_budget_fallback`)
- Improved GPU/VRAM comparability gating:
  - process-scoped VRAM measurement via `detect_process_vram_mb(...)`
  - explicit runtime reduced-GPU blocked mode unless `TRIAGE_ALLOW_REDUCED_GPU_BENCHMARK=1`
  - runtime CPU fallback threshold controlled by `TRIAGE_RUNTIME_CPU_FALLBACK_MB`
  - guarded CPU benchmark sample cap (`TRIAGE_CPU_GUARD_MAX_SAMPLES`) marked non-comparable (`blocked`)
- Added latency-outlier reclassification for same-hash variance:
  - `load_recent_keep_latencies_for_state_hash(...)`
  - `detect_latency_outlier_for_state_hash(...)`
  - outlier `discard` becomes `blocked` when above median-based ratio gate
- Added latency tag normalization helper to avoid duplicate `[latv2]` prefixing in descriptions.
