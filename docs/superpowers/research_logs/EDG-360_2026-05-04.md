## Problem Statement
- Repeated non-comparable blocked runs are intentionally short-circuited to preserve loop throughput.
- If blocked rows are included in generic state-hash dedupe, new logic changes that share a hash can be skipped too aggressively.
- Existing state hashing used weaker coverage for image payload integrity and transient runtime toggles that could destabilize comparability.

## Code Changes Consolidated for EDG-360
Updated `triage_sandbox.py` and `tests/test_triage_sandbox.py` to:
- Keep blocked rows out of generic state-hash dedupe (`DEDUP_STATUSES` excludes `blocked`), while preserving reason-specific blocked short-circuits.
- Add reusable blocked-reason matching helper:
  - `has_blocked_reason_for_state_hash(...)`
- Add same-hash latency history + outlier detector helpers:
  - `load_recent_keep_latencies_for_state_hash(...)`
  - `detect_latency_outlier_for_state_hash(...)`
- Add probe-budget helper:
  - `consume_probe_budget(...)`
- Harden `compute_state_hash()`:
  - migrate to `sha256`
  - hash full image payload bytes (not only prefix)
  - include stable runtime knobs that materially affect comparability
  - explicitly ignore transient pre-import guard activation bit
- Keep duplicate blocked-state pre-load short-circuits active for known non-comparable reasons.
- Promote experiment signature to:
  - `edg360-r1-statehash-hardening-and-blocked-dedupe-boundary-latv2-nctx933-gpu47-probebudget11`
