# EDG-355 - Edge-Triage Optimization Loop (2026-05-03)

## Wake Delta Handling
- Wake reason: `issue_assigned`
- New action: continue throughput-focused optimization for repeated blocked GPU-inactive runs.

## Problem Statement
- Existing pre-load short-circuits handled duplicate blocked states for:
  - `pre-import low-vram cpu guard active`
  - `post-load gpu telemetry unavailable`
  - `post-load gpu offload guard triggered`
- Another repeated blocked path still paid model/chat initialization cost before exiting:
  - `blocked: GPU offload unavailable (CPU-only runtime); skipped guarded CPU benchmark...`
- On stable CUDA-inactive hosts with unchanged state hash, this created avoidable per-heartbeat startup overhead.

## Code Change (r1)
Updated `triage_sandbox.py`:
- Added a new pre-load duplicate blocked-state short-circuit in `run_triage()` under:
  - `N_GPU_LAYERS > 0`
  - `TRIAGE_ALLOW_GUARDED_CPU_BENCHMARK=0`
  - `torch.cuda.is_available() == False`
- New reason fragment check:
  - `gpu offload unavailable (cpu-only runtime)`
- If prior blocked row for same `state_hash` exists with that fragment:
  - prints duplicate blocked-state message
  - calls `cleanup_after_run()`
  - returns `{"status": "blocked", "state_hash": current_hash}`
  - skips `Llava15ChatHandler(...)` and `Llama(...)` initialization.

Also updated experiment signature:
- `edg355-r1-latv2-preload-short-circuit-duplicate-cpu-offload-unavailable-blocked-nctx933-gpu47-probebudget11`
