# EDG-341 - Comparability Guard Hardening and State-Hash Refresh (2026-05-02)

## Objective
- Harden experiment comparability and dedupe behavior in the optimization loop.
- Improve runtime accounting fidelity (process-scoped VRAM) without changing classification prompts.
- Validate whether these guard/accounting changes preserve frontier performance under current promoted runtime defaults.

## Changes
- Set a fresh experiment signature for this guard/accounting update:
  - `edg341-r1-latv2-guard-comparability-vram-scope-hash-hardening-nctx933-gpu47-probebudget11`
- Added explicit runtime CPU fallback knob compatibility:
  - Prefer `TRIAGE_RUNTIME_CPU_FALLBACK_MB`
  - Fallback to legacy `TRIAGE_PREIMPORT_CPU_FALLBACK_MB`
- (From active EDG-341 patch set) tightened comparability controls and observability:
  - Exclude `blocked` rows from state-hash dedupe.
  - Use SHA-256 state hash with full image-content hashing.
  - Treat transient pre-import guard activation as non-hashable runtime noise.
  - Add targeted-probe per-bucket budget fallback accounting.
  - Add process-scoped VRAM measurement via `nvidia-smi --query-compute-apps`.
  - Block non-comparable guarded/reduced-GPU benchmark paths unless explicitly allowed.

## Rationale
- F1 remained at frontier (`0.9794`) across all six runs.
- Latency remained in a tight high band (~`266-267 ms`) even under forced reruns and GPU-layer sweep.
- The slowdown is therefore stable for this patch/runtime combination and not caused by one-off host contention.
- Guard and hash-hardening changes still improve loop hygiene by preventing non-comparable runs from contaminating optimization decisions.
