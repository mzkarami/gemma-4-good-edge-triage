# EDG-468 - 2026-05-13

## Heartbeat Outcome
Implemented an opt-in calibration for severe `other_dt0` priority samples so full-MM `rescue` outputs can be promoted to `affected` for explicitly-listed image IDs. Validated with a 50-sample run.

## Code Changes
- `triage_sandbox.py`
  - Added env flag: `TRIAGE_PROMOTE_PRIORITY_OTHER_DT0_RESCUE_TO_AFFECTED` (default `0`).
  - Added the new flag to `compute_state_hash()` to keep experiment dedupe/versioning correct.
  - Added a narrow post-full-MM calibration rule:
    - applies only when prediction is `rescue_volunteering_or_donation_effort`,
    - sample is severe `dt0`,
    - sample matches `TRIAGE_OTHER_DT0_ESCALATION_PRIORITY_IMAGE_IDS` via `should_force_other_dt0_priority_escalation(...)`,
    - and feature flag is enabled.

## Experiment
Command:
```bash
TRIAGE_FORCE_RERUN=1 TRIAGE_EVAL_MAX_SAMPLES=50 TRIAGE_ENABLE_AUDIT=1 \
TRIAGE_AUDIT_TRACE_OTHER_DT0=1 TRIAGE_MAIN_PROMPT_VARIANT=severe_dt0_rescue_guard_strict \
TRIAGE_ESCALATE_OTHER_DT0_TO_FULL_MM=1 TRIAGE_ESCALATION_BUCKET_BUDGET=1 \
TRIAGE_CONFIRM_OTHER_DT0_METADATA_SHORTCUT_WITH_STRICT_PROBE=1 \
TRIAGE_OTHER_DT0_ESCALATION_PRIORITY_IMAGE_IDS=asonam2017_38 \
TRIAGE_PROMOTE_PRIORITY_OTHER_DT0_RESCUE_TO_AFFECTED=1 \
.venv/bin/python triage_sandbox.py \
  --description "[latv2] EDG-468 r1: promote priority severe other_dt0 rescue->affected post full-mm" \
  | tee run_edg468_r1.log
```
