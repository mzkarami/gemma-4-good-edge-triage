# EDG-357 - Edge-Triage Optimization Loop (2026-05-04)

## Wake Delta Handling
- Wake reason: `issue_assigned`
- New action: continue throughput optimization by removing repeated startup cost on non-comparable guarded-CPU diagnostic repeats.

## Problem Statement
- Guarded CPU diagnostic runs (`TRIAGE_ALLOW_GUARDED_CPU_BENCHMARK=1`) are intentionally capped and then marked blocked as non-comparable.
- Before this change, duplicate detection for this blocked state happened only after model/chat initialization and cap setup.
- On CUDA-inactive hosts, repeated forced reruns of the same state hash still paid avoidable model startup overhead.

## Code Change (r1)
Updated `triage_sandbox.py`:
- Added pre-load duplicate blocked-state short-circuit in `run_triage()` for guarded CPU capped-diagnostic rows.
- New pre-check condition:
  - `TRIAGE_ALLOW_GUARDED_CPU_BENCHMARK=1`
  - `EVAL_MAX_SAMPLES <= 0`
  - `TRIAGE_CPU_GUARD_MAX_SAMPLES > 0`
  - `(N_GPU_LAYERS > 0 and CUDA inactive) OR pre-import GPU guard active`
  - Existing blocked row for same `state_hash` containing reason fragment:
    - `guarded cpu fallback used capped sample diagnostic run`
- Behavior on match:
  - prints duplicate blocked-state message
  - calls `cleanup_after_run()`
  - returns `{"status": "blocked", "state_hash": current_hash}`
  - skips `Llava15ChatHandler(...)` and `Llama(...)` initialization.

Also updated experiment signature:
- `edg357-r1-latv2-preload-short-circuit-duplicate-guarded-cpu-cap-blocked-nctx933-gpu47-probebudget11`
