# EDG-351 - Edge-Triage Optimization Loop (2026-05-03)

## Wake Delta Handling

## Problem Statement
- EDG-350 introduced sample capping (`max_samples=4`) for guarded CPU diagnostics when GPU was requested but inactive.
- Repeated heartbeats on the same state hash could still re-run those 4 diagnostic samples, even when an equivalent blocked row already existed.
- This created avoidable duplicate runtime in non-comparable host conditions.

## Code Change (r1)
Updated `triage_sandbox.py`:
- Added an early short-circuit immediately after guarded CPU sample-cap activation.
- If `has_blocked_reason_for_state_hash(...)` already finds a blocked reason containing:
  - `guarded cpu fallback used capped sample diagnostic run`
- Then the run exits before `evaluate_triage(...)` with:
  - `{"status": "blocked", "state_hash": current_hash}`
- This preserves existing comparability rules while removing duplicate diagnostic inference work.

Also updated experiment signature:
- `edg351-r1-latv2-skip-duplicate-guarded-cpu-capped-diagnostic-nctx933-gpu47-probebudget11`
