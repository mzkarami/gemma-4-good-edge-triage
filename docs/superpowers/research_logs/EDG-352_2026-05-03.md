# EDG-352 - Edge-Triage Optimization Loop (2026-05-03)

## Wake Delta Handling
- Wake reason: `issue_assigned`
- New action: continue optimization loop with a throughput improvement for repeated blocked CPU-diagnostic hosts.

## Problem Statement
- Existing logic already blocked non-comparable runs when post-load GPU telemetry was unavailable and CUDA runtime was inactive.
- Under `TRIAGE_FORCE_RERUN=1`, repeated heartbeats on unchanged state hashes could still re-run model initialization before hitting the same blocked exit.
- This caused avoidable startup overhead on hosts that remain CUDA-inactive.

## Code Change (r1)
Updated `triage_sandbox.py`:
- Added a pre-load short-circuit after state hash resolution and dedupe checks.
- New behavior applies when all are true:
  - `N_GPU_LAYERS > 0`
  - `TRIAGE_ALLOW_GUARDED_CPU_BENCHMARK=0`
  - `torch.cuda.is_available()` is false
  - a prior blocked row exists for same `state_hash` containing:
    - `post-load gpu telemetry unavailable`
- In that case, the run exits early with:
  - `{"status": "blocked", "state_hash": current_hash}`
- It also performs `cleanup_after_run()` and skips model load entirely.

Also updated experiment signature:
- `edg352-r1-latv2-preload-short-circuit-duplicate-postload-telemetry-blocked-nctx933-gpu47-probebudget11`

- EDG-352 reduces repeated heartbeat overhead for known CUDA-inactive blocked states by skipping unnecessary model initialization.
- Comparable benchmark behavior remains unchanged when CUDA becomes available again.
